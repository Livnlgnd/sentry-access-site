Doors & rules

The decision reaches the strike, not just the screen.

Pulse an Axis network door controller or a generic HTTP relay only after identity and local policy both pass. Schedules, holidays, roles, and fail-closed behavior run on site.

Relay settingsI/O port, 1–30 second pulse, active state open or closed.

Local policy

  • Weekly windows, multiple windows, overnight windows, and holiday closures.
  • Role authorization per door: Employee, Contractor, Visitor, Administrator.
  • Kiosk door binding: this kiosk unlocks this door after a granted verification.
  • Manual unlock for commissioning, attributed to the signed-in operator.
  • Controller test verifies reachability, credentials, and output direction.

Fail-closed behavior

A denied request never opens the strike. That includes a disabled door, missing schedule, unauthorized role, missing controller, timeout, or a kiosk without the desktop door bridge.

Safety: use a fail-safe strike with independent request-to-exit and fire-alarm release. Test egress with the software powered off. This release does not supervise REX or door-position inputs, detect held/forced doors, or enforce anti-passback.
