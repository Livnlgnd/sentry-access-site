Camera gateway

Reuse the cameras already on the wall.

Pull RTSP or NVR substreams into the local face engine. The gateway logs only matched enrolled identities, never unknown passersby, and never stores or uploads frames.

RTSP / RTSPSHTTP MJPEGNVR channelsBundled FFmpeg

Ingest and processing

  • RTSP, RTSPS, HTTP MJPEG, and NVR channel URLs.
  • Bundled FFmpeg; no separate installation on the kiosk.
  • Default sampling at 2 FPS and 960 px working width.
  • Face detection and matching run locally against enrolled templates.
  • 60-second per-camera/per-identity cooldown to avoid duplicates.
  • Automatic reconnect and visible stream status.

What gets logged

Matched identityName, employee ID, role, confidence, distance, threshold.
Camera contextCamera name, location, timestamp, quality.
Unknown facesNot identified and not logged.
Video framesDecoded in memory only; never written or uploaded.
CredentialsRTSP URLs and passwords stay in the OS keystore.
Current limits: one face is processed per sampled frame. In a busy lobby, two people walking together can mean one goes unobserved. There is no automatic ONVIF discovery, continuous recording, live view, PTZ, audio, LPR, or Ring support.

NVR caveat

Many NVR PoE ports isolate cameras on a separate subnet. If the camera IP is unreachable from the kiosk, use the NVR channel RTSP URL or enable the NVR’s virtual-host/camera-access feature.

Background behavior

Closing the window while cameras are enabled minimizes the gateway to the system tray. Quit explicitly from the tray to stop processing.
